# M2 Buying Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the inherited purchase logic with a buyer that values every purchase by the income it adds, including click income at the game's real cap, golden cookie income from the game's live rules, and the achievements a purchase would earn; and make ranking cheap enough that the harness runs at hundreds of times real time again.

**Architecture:** Three layers. `src/core/income.js` and `src/core/buyer.js` are pure: they turn numbers into an income estimate and a ranked purchase list. `src/game/measure.js` reads the live game into those numbers and runs what-ifs through the M1 guard. `src/systems/buyer.js` is the loop system that decides and buys, and the legacy functions that other legacy code still calls become thin adapters over it.

**Tech Stack:** As M1. New code runs on the M1 loop and guard; no timers.

**Spec:** `docs/superpowers/specs/2026-09-29-mushie-cookies-design.md`, section 6, M2. Mechanics: `docs/research/game-mechanics-2.053.md` sections 5 (golden cookies), 9 (wrinklers), 10 (CpS). Prior art: `docs/research/ecosystem-survey.md`, Cookie Monster and Cookie Payback Planner entries.

## Global Constraints

- Everything in the M1 plan's Global Constraints.
- Fair play: the buyer reads any state, acts only through `building.buy(n)`, `upgrade.buy()`, `building.sell(n)`.
- Every what-if goes through `src/core/sim.js`. No code outside it changes game state to measure something.
- The click rate used for valuation is the game's cap: 50 clicks per second when autoclick is on (`Game.ClickCookie` rejects clicks under 20 ms apart), or the configured speed if lower.
- Ranking cost target: a full ranking pass under 10 ms in the harness at mid-game (about 60 candidates). Harness speed target with buying on: at least 300 times real time.
- No static table is added. Building tier thresholds, achievement thresholds and golden cookie rules are read from the game (`Game.Tiers`, `Game.UnlockTiered`, `Game.shimmerTypes.golden`) or copied from `main.js` with the line cited in a comment.
- Nothing in this milestone changes ascension, combos, garden, market, lumps or gods.

## Review Focus

1. **A purchase that unlocks a tier upgrade or earns an achievement.** The what-if must include the unlock and the achievement's milk. Pinned in Task 3.
2. **The bank reserve.** Holding cookies for Lucky must never block a purchase that pays back faster than the reserve does, and must never let the bank drop below zero. Pinned in Task 4.
3. **An upgrade with no CpS effect** (golden cookie upgrades, mouse upgrades, discounts). It must get a finite, correctly signed value, never infinity and never zero when it has one. Pinned in Tasks 1 and 4.
4. **Post-ascension bulk buying.** With a bank thousands of times larger than the next price, the buyer must reach the right building counts within a game minute without buying past the point where the next purchase is a worse deal. Pinned in Task 5.
5. **Building limits and blacklists from the settings** (mine, factory, tower, orb limits; the blacklist presets). A limited building is never bought past its limit. Pinned in Task 5.

### Task 1: Income model

**Files:**
- Create: `src/core/income.js`, `src/core/goldenPool.js`
- Test: `test/unit/income.test.mjs`, `test/unit/goldenPool.test.mjs`

**Interfaces:**
- `outcomeProbabilities(rules)`, from `goldenPool.js`. `rules` mirrors the flags the game consults when it builds its list (`main.js:5424-5447`): `{ wrath: 0|1, scorn: boolean, chainEligible: boolean, fools: boolean, dragonflightActive: boolean, buildingSpecial: boolean, lumps: boolean, reaper: number, dragonflight: number }`, where `reaper` and `dragonflight` are the aura multipliers (0, 1 or 1.1). Returns `{ [outcome]: probability }` summing to 1, computed by enumerating every combination of the game's independent rolls and averaging the uniform choice over each resulting list. The "80% chance to avoid repeating the last outcome" rule is ignored; its effect is second order.
- `estimateIncome(state)`, from `income.js`. `state`:

```js
{
  cps,                 // unbuffed cookies per second, after wrinkler withering (Game.unbuffedCps)
  clickPower,          // cookies per click with no click buff (Game.computedMouseCps)
  clicksPerSecond,     // 0 when autoclick is off
  bank,                // cookies held
  wrinklers: { count, returnMult },   // expected wrinklers sucking and the payout multiplier per wrinkler (1.1 × modifiers)
  golden: {
    meanInterval,      // seconds between natural golden cookies, from the spawn window
    durationMult,      // effectDurMod
    gainMult,          // mult
    probabilities,     // from outcomeProbabilities
    buildingSpecialMean, // mean amount over buildings with 10 or more, 0 if none
  },
}
```

Returns `{ total, passive, click, golden, byOutcome }` in cookies per second, where:
- `passive = cps × wrinklerMultiplier`, with `wrinklerMultiplier = 1 − 0.05·count + 0.05·count·count·returnMult` (`main.js:14393`: every sucking wrinkler stores the whole withered amount).
- `click = clicksPerSecond × clickPower`.
- Buffs are treated as independent renewal processes: outcome *o* with probability *p* and duration *d* is active a fraction `f = p·d / meanInterval` of the time (capped at 1). CpS-multiplying outcomes (frenzy ×7, dragon harvest ×15, building special ×(1 + mean/10), blood frenzy ×666, clot ×0.5) contribute `(mult − 1)·f·passive`, click multipliers (click frenzy ×777, dragonflight ×1111, cursed finger as 0 click but `cps × duration` per click) contribute `(mult − 1)·f·click`. Overlaps multiply: the passive term is `passive × Π(1 + (m−1)·f)` and likewise for click, which is what independence gives.
- Lucky: `p × (min(0.15·bank, 900·cps)·gainMult + 13) / meanInterval`. Ruin: `−p × (min(0.05·bank, 600·cps) + 13) / meanInterval`.
- Chain and storm: chain payout ≈ `min(6·3600·cps, 0.5·bank)·gainMult × 0.5` (the chain usually ends about halfway to its cap); storm ≈ `7·30·0.5·4·60·cps × 0.5`, halved because drops must be reached before they expire even with autoclick. Both are approximations and are marked as such in the code.
- Durations: frenzy 77, dragon harvest 60, blood frenzy 6, clot 66, click frenzy 13, dragonflight 10, cursed finger 10, building special 30, all × `durationMult` (`main.js:13862-13972`).

### Task 2: Reading the game

**Files:**
- Create: `src/game/measure.js`
- Test: `test/game/measure.test.mjs`

**Interfaces:**
- `readState(game, settings)` returns the `state` object of Task 1 from the live game. Sources:
  - `cps`: `game.unbuffedCps`
  - `clickPower`: `game.computedMouseCps` divided by the product of active click buffs' `multClick` (so it is the unbuffed value)
  - `clicksPerSecond`: `settings.autoClick ? Math.min(settings.cookieClickSpeed, 50) : 0`
  - `wrinklers.count`: 0 if `game.elderWrath == 0`; else `game.getWrinklersMax()` (the game's own count; check its name in `main.js` near line 14264)
  - `wrinklers.returnMult`: `1.1 × (Sacrilegious corruption ? 1.05 : 1) × (Wrinklerspawn ? 1.05 : 1) × (1 + 0.2·auraMult('Dragon Guts')) × Skruuia factor` (`main.js:14467-14479`)
  - `golden.meanInterval`: the spawn window from `game.shimmerTypes.golden.getMinTime(type)` and `getMaxTime(type)` in frames. The spawn chance per frame rises as `((t − min)/(max − min))^5`, so the expected spawn time is `min + (max − min) × E`, where `E` is the mean of that distribution. Compute `E` once numerically (a loop over 10,000 steps) and cache it; it is about 0.86. Divide by `game.fps` for seconds. Add the mean on-screen life (`13 s` × modifiers, `main.js:5369-5381`) since the next timer starts when the cookie is gone.
  - `golden.durationMult`, `golden.gainMult`: the products at `main.js:5459-5488`, read through `game.Has`, `game.auraMult`, `game.eff`, `game.hasGod`.
  - `golden.probabilities`: `outcomeProbabilities` with the flags read from the game; for wrath, weight by `game.elderWrath` (1 → 1/3 wrath, 2 → 2/3, 3 → all, Skruuia → all, `main.js:5325`) and mix the two distributions.
  - `golden.buildingSpecialMean`: mean `amount` over buildings with `amount >= 10`.
- `measureCandidates(game, settings, candidates)`: for each candidate `{ apply }` runs a what-if and returns `readState` after it; uses `simulateEach` from Task 3.

### Task 3: Cheap, achievement-aware what-ifs

**Files:**

- Test: `test/unit/sim.test.mjs` (extend), `test/game/sim.test.mjs` (extend)

**Interfaces:**
- `simulateEach(game, trials, measure)`: takes ONE snapshot and stubs `Win` once; for each `{ apply }` in `trials`: `apply()`, `recalculateGains = 1`, `CalculateGains()`, `measure()`, then restores the snapshot. Closes with `Win` restored, one `CalculateGains`, and the highest-CpS rule from `simulate`. Returns the array of measurements. Cost per trial: one recalculation plus one restore, instead of two recalculations.
- The Win stub becomes a shim that marks achievements won inside the what-if without notifying, so that `CalculateGains` sees their milk: `it.won = 1; if (game.CountsAsAchievementOwned(it.pool)) game.AchievementsOwned++`. Arrays are handled as the game does. The snapshot already restores `won` and `AchievementsOwned`.
- `awardForBuildings(game, building)`: calls `game.UnlockTiered(building)` (tier upgrades and tier achievements, `main.js:9916-9921`) and awards the total-count achievements from `main.js:16457-16463` (Builder 100, Architect 500, Engineer 1000, Lord of Constructs 2500, Grand design 5000, Ecumenopolis 7500, Myriad 10000). `awardForUpgrades(game)`: `main.js:16465-16473` (Enhancer 20, Augmenter 50, Upgrader 100, Lord of Progress 200, The full picture 300, When there's nothing left to add 400, Kaizen 500, Beyond quality 600, Oft we mar what's well 700). ### Task 4: Candidates and ranking

**Files:**
- Create: `src/game/candidates.js`, `src/core/buyer.js`
- Test: `test/unit/buyer.test.mjs`, `test/game/candidates.test.mjs`

**Interfaces:**
- `listCandidates(game, settings)` returns:
  - one per building not excluded by settings (`blacklist`, `mineLimit/mineMax`, `factoryLimit/factoryMax`, `towerLimit/manaMax`, `orbLimit/orbMax`, the Spontaneous Edifice cap on You at 399): `{ key: 'building:<name>', kind: 'building', name, price: building.getPrice(), apply() }` where `apply` adds one, calls `awardForBuildings`;
  - one per upgrade in `game.UpgradesInStore` whose `pool` is `''`, `'cookie'` or `'tech'`, minus the ids the legacy `recommendationBlacklist` lists and minus toggles: `{ key: 'upgrade:<id>', kind: 'upgrade', price: upgrade.getPrice(), apply() }` where `apply` sets `bought = 1`, `UpgradesOwned++`, calls `awardForUpgrades`, and for the research chain also sets `Game.elderWrath` as the upgrade's own `buyFunction` would (read `upgradeJson` for the wrath stage; it is the one side effect worth modelling);
  - one **chain** per locked tier upgrade of each building whose unlock threshold is within `settings.chainReach` (default 15) more buildings: `{ key: 'chain:<upgrade id>', kind: 'chain', price: sum of the next n building prices (geometric, `basePrice × 1.15^k`, through `building.getPrice()` after each apply) + upgrade price, steps: n, apply() }` applying all of it. Chains use `game.Tiers[tier].unlock` and `building.tieredUpgrades`; no static table.
- `rankCandidates({ candidates, measured, income, bank })`: pure. For each candidate `deltaIncome = measured[i].total − income.total`; `payback = max(price − bank, 0) / income.total + price / deltaIncome`; `Infinity` when `deltaIncome <= 0`. Returns candidates sorted by payback then by deltaIncome descending, each with `{ deltaIncome, payback }`.
- `chooseReserve({ best, reserves, income })`: `reserves` are `{ amount, incomeAt }` for banks 0, `6000·cps` (Lucky) and `42000·cps` (Lucky under Frenzy); a reserve's payback is `amount / (incomeAt − income.total)`. Returns the largest reserve whose payback is at most `best.payback`, else 0.
- `decide({ ranked, reserve, bank })`: returns the first candidate whose `price + reserve <= bank`, or null if the best candidate is unaffordable (waiting is the decision: buying something worse first is what the payback ordering already priced in).
